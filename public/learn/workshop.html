Workshop: Build Reliable Multilingual Voice AI Agents

A hands-on 90-minute session for developers, analysts and students. You work with a small fictional logistics agent and learn where voice agents fail and how to catch it.

  • 90 minutes
  • Beginner friendly
  • No ElevenLabs account needed
  • 0 credits for all core exercises
  • Synthetic data only

Status

These are prepared, tested materials. No workshop has been scheduled or delivered. There is no date, venue, sponsor or attendee yet. The project is independent and not affiliated with or endorsed by ElevenLabs. You are free to run the workshop yourself under the repository’s MIT licence.

Learning objectives

After the session a participant can:

  1. Describe the path of a voice request: speech in, recognition, agent decision, tool call, response, speech out.
  2. Name five safe outcomes — clarify, abstain, recover, escalate, reject — and say when each applies.
  3. Write a failing test for a business rule and make it pass without weakening the rule.
  4. Tell fixture evidence from provider evidence and explain why the difference matters.
  5. Explain why “escalated to a human” must not be reported as “approved”.

Prerequisites

  • A laptop with Node.js 24 and a text editor.
  • Git, or the repository downloaded as a ZIP file.
  • Basic JavaScript reading ability. You do not need to have built an agent before.

Not needed: an ElevenLabs account, an API key, a paid plan, a microphone or a voice recording.

Introduction for beginners

A voice agent listens, decides and speaks. On the ElevenLabs platform the listening and speaking are handled for you. The deciding is done by a language model following your prompt, and it can call tools — functions you provide — to look things up or request actions.

Every arrow can fail on its own. This workshop concentrates on the highlighted box, because it is the part you write yourself and the part you can test for free. The fictional setting: a terminal where shipment HV-101 is held at gate B.

Exercises

Predict the result before you run each one. Being wrong on paper first is the point.

1. Break a business rule

In starter/agent.mjs change the status of HV-101 to "released" and run the tests.

Expected: “known record stays held” fails, 7 pass. Restore the record.

2. Add a boundary test

Write a test in which the lookup returns gate "Z" for HV-101. Decide the outcome before running it.

Expected: escalate. Unknown values go to a person; they are not accepted to make a test pass.

3. Make the source fail

node -e '
import("./community/elevenlabs-belgium/starter/agent.mjs").then(async (m) =>
  console.log(await m.handle("HV-101", async () => { throw Error("timeout"); })));'

Expected:

{
  outcome: 'recover',
  message: 'The source is unavailable. No release has been confirmed.'
}

Discuss: why is retrying forever unsafe, and why does the message not repeat “timeout”?

4. Same rule, three languages

A caller says “Waar is mijn zending?” or “Où est ma livraison ?”. Which piece of information is missing? Write the clarifying question in both languages.

Expected: the outcome is clarify in every language. This is a discussion about intent, not a measurement of translation quality.

5. Read evidence in AgentProof

Open AgentProof. Filter to failed scenarios, search HV-301, read expected versus observed, then switch the evaluation run to the corrected fixture. Export the evidence and find evidenceType, sourceCommit and limitations.

Expected: you can explain why “110 of 110” for the corrected fixture does not prove a real agent is reliable.

6. Design your own failure case

Invent one new way the agent could be fooled, with no personal data. Write the expected outcome first, then the test.

Expected: a test that distinguishes a safe response from a merely helpful-sounding one.

Cost-safe mode

Everything above runs locally and costs 0 credits per participant. It is the default and it is a complete workshop.

A facilitator may show a real agent in their own account as a demonstration. If participants want to try a live agent, they use their own account, outside the core path. Before offering that, work out the cost from the current price list: 

participants × sessions each × maximum minutes × current credits per minute
+ a margin for model and tool overhead

Check the live price on the day. If you cannot get a current figure, stay offline. Never put an organiser’s API key in a shared file, a slide or browser code.

Facilitator notes

  • Before: on a clean checkout run the setup above and open the slides. Check projector contrast and that code is readable from the back row.
  • Pairs: 10–15 learners in pairs works well with one facilitator.
  • Predict first: ask for a show of hands on the outcome before each run.
  • Timeout exercise: a friendly answer must not claim release. Let the room argue recover versus escalate; both can be defended, and saying why is the lesson.
  • AgentProof: the baseline’s 30 failures are scripted on purpose. Ask why a perfect corrected score is not evidence about a model.
  • Languages: invite Dutch and French speakers to phrase the clarifying question. Do not grade pronunciation or fluency.
  • Accessibility: every exercise is text-based. Nobody has to speak or be recorded. Provide the printed handout and allow extra time.
  • Privacy: no recording by default. Collect feedback only with consent, and say how it can be deleted.
  • Fallback: if the network fails, the starter and the slides still work offline.

The full runbook is in instructor-notes.md.

Troubleshooting

ProblemWhat to do

A test fails that should passYou probably left an edit from exercise 1. Run git checkout -- community/elevenlabs-belgium/starter.
Port 4313 is in useUse the hosted AgentProof link instead of the local preview.
AgentProof shows no data locallyRun node --import tsx scripts/phase3/benchmark.ts, rebuild and reload.
No ElevenLabs account or creditsNot needed. Complete the whole core path offline.
Windows quoting errors in exercise 3Use Git Bash or WSL, or put the three lines in a file named try.mjs and run node try.mjs.
